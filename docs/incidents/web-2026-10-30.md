# apps/Web: '/' cannot be found

**Status:** Resolved (2026-10-30)

## Symptom
Opening `http://localhost:5173/` renders React Router's error
"`No routes matched location "/"`" instead of the app.

## Root cause
`apps/web/src/router.tsx` defined `/pay/:token` and the `/dashboard/*`
subtree but **no route for `/`**. There is a dashboard route for
`/dashboard` (redirecting to `/dashboard/transactions`) and an auth guard on
the dashboard subtree, so any sane root should bounce through them. This is a
runtime-only bug: nothing unit-testable sees a browser landing on the origin
root.

## Fix
Added `{ path: "/", element: <Navigate to="/dashboard" replace /> }` as the
first route — the root now lands in the dashboard shell, which redirects to
`/dashboard/transactions`, and unauthenticated users are sent to
`/dashboard/login`. Also removed the stale `// MK: /refunds route removed
until FP-212` comment (FP-212 shipped; refunds live in the transaction page
drawer, no separate route).

## Verification
Web typecheck clean; `vite build` succeeds (69 modules). The admin console was
checked for the same class: its router already handles `/` correctly (guarded
redirect to `/merchants` inside `RequireAdminAuth`) — no fix needed there.
